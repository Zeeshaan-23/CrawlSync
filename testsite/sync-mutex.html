Mutual Exclusion & Critical Section Design

Ensuring exclusive execution across concurrent goroutines.

The Golden Rule of Critical Sections

A critical section is a block of code accessing shared mutable state that must not be concurrently executed by multiple threads. In CrawlSync:

Never perform network I/O or disk operations while holding a mutex.

Holding locks during slow HTTP calls serializes the entire worker pool, turning a concurrent program into a sequential bottleneck. CrawlSync strictly acquires locks only to inspect or mutate in-memory maps, immediately releasing them before network fetching.
